**加回来的做法**：在对应目录下建 `pipeline/进入游戏/`，放两个文件（⚠️ **必须真把 json 放进去，光建空文件夹会让整个资源包加载失败**，原理见 [5.2](#52-发版打包踩坑记录) 第 2 条）——

```jsonc
// 打开游戏.json —— 覆写 base 里的节点，只改包名
{
    "启动并进入游戏": { "package": "包名" },
    "模拟器包名游戏启动": { "action": "StartApp", "package": "包名" }
}
```

```jsonc
// 停止游戏.json
{
    "关闭游戏": { "action": "StopApp", "package": "包名", "next": [] }
}
```

> ⚠️ **B 服是特例**：它的 `打开游戏.json` 里 `启动并进入游戏` 写了一大串 `[JumpBack]xxx` 的 next 节点（游戏需在客户端进行更新、舰长~真的要退出游戏吗-否、B服账号登录……），这些节点**必须先在 `base/pipeline` 里存在**，否则资源包加载时会直接报
> `PipelineChecker::check_next_list Invalid next node name` → **发版失败**。其余 6 个渠道服只覆写包名，不引用额外节点，所以没这个问题。
>
> 另：目录名 `resource_OPPE` 是 `OPPO` 的笔误，但 interface.json 里引用的就是这个名字，要改得两边同步。

### 5.2 发版（打包）踩坑记录

发版链路：`tools/install.py`（桌面端）/ `.github/workflows/install.yml` 的 android job → 都会调用 `tools/ci/gen_resource_hash.py` **逐个 resource 条目算 hash**，任何一条加载不了就会失败。

已知会导致失败的**四种**情况（都是本地实测出来的）：

1. **resource 条目里的 path 指向不存在的目录** → `FileNotFoundError`。
2. **bundle 目录是空的：里面连一条能解析的 pipeline json 都没有** → `PipelineResMgr::load_all_json failed`，`post_bundle` 返回失败。
   - 这**就是"渠道服文件夹里没内容就发版失败"的真正机制**：光建一个空文件夹不算数（git 本来也不跟踪空目录），**一个 resource 条目引用的目录里必须至少有 1 个 json 文件**。
   - `resource_adb` 目前靠 [`pipeline/_占位.json`](../assets/resource/resource_adb/pipeline/_占位.json) 撑着（里面只有一个 `DoNothing` 的占位节点）。等 adb 端真实节点（游戏启动/停止）搬进去之后，这个占位文件就能删。
   - 实测记录：空目录 `post_bundle = False`；放进占位 json 后 `post_bundle = True`。
3. **pipeline 里 next 引用了不存在的节点** → `PipelineChecker: Invalid next node name`。这就是之前 B 服把发版搞挂的原因（当时 `base` 里还一条 pipeline 都没有）。
   - ⚠️ 所以 [四](#四渠道服包名汇总) 里 B 服那种带一长串 `[JumpBack]xxx` 的写法，**必须等 base 里那些节点都存在了**再启用，否则一加回来就炸。
4. **`assets/tasks` 目录不存在** → `tools/install.py` 的 `copytree(assets/tasks)` 直接抛异常（interface.json 里 import 了一堆 `tasks/*.json`）。
   - 现在目录已经建好（放了抓回来的 `工具/圣痕洗词缀.json`），不会再缺。
