# 圣痕洗词缀（智能版）

Maa_bbb 的「圣痕洗词缀」增强实现。与原有的正则版任务并存，互不影响。

## 一、前因

原有的「洗词缀」任务要求用户手写一条正则表达式来决定"什么样的新词缀算好"，
实际使用中有几个问题：

- **要写正则**：换一个角色属性、换一把武器就得回去改正则，改错一个字符就默默不生效；
- **只看新词缀**：只识别「新词缀技能」那一块，不读「旧词缀技能」，
  因此无法比较"洗出来的"和"现在身上的"哪个更好；
- **不会点按钮**：识别命中的两个节点既没有 action 也没有 next，
  命中后任务直接结束，「写入新词缀」「保留旧词缀」从来不会被点，仍要手动操作。

而游戏内的词缀种类其实是有限的：6 种角色属性、若干武器分组，
外加一条无条件的「攻击提升」。既然种类有限，就没有必要让用户写正则。

## 二、现在的功能

新增任务「**圣痕洗词缀（智能版）**」，两组下拉框取代正则：

| 控件 | 说明 |
| --- | --- |
| 洗词缀模式 | **直接洗词缀**（普通重构）/ **词缀锁洗词缀**（定向重构） |
| 确认使用词缀锁 | 防误触开关，只有词缀锁模式需要选「是」 |
| 单条高攻 | 打开后，任意一条词缀达到「单条达标值」也算达标 |
| 单条达标值 | 默认 22.9 |
| 角色属性 | 生物 / 机械 / 异能 / 量子 / 虚数 / 星尘 |
| 武器类别 | 6 组（同一条词缀会同时涵盖多种武器，按组选即可） |
| 目标总攻击力 | 两条有效攻击力之和要达到的值 |
| 重构次数上限 | 默认 500，防止一直刷下去 |

功能要点：

1. **同时读新旧两批词缀**，只统计对当前角色有效的词条，算出各自的 **有效总攻击力** ；
2. **刷到更好的就先写入保底** —— 只要新的总攻击力更高就先点「写入新词缀」，
   哪怕还没到目标，再继续冲目标，中途刷到的好词缀不会丢；
3. **旧词缀达标即结束**，并按「保留旧词缀」收尾，离开时界面是干净的；
4. **词缀锁模式**只洗未锁定的那一条，并且会自动确认"确实锁了一条"。

## 三、实现方法

### 1.有效词条怎么判定

只有三类词条计入"有效总攻击力"：

| 类别 | 文本形式 | 有效条件 |
| --- | --- | --- |
| 角色属性 | `{属性}角色攻击提升xx.x` | 与所选属性一致 |
| 武器类别 | `{武器…}角色攻击提升xx.x` | 文本里出现的武器**全部属于**所选武器组（不要求列全、不要求顺序） |
| 无条件 | `攻击提升xx.x` | 任何角色都有效 |
| 其它 | `暴击伤害提升4.95%`、`生命上限提升235.4` … | 一律按 0 计 |

一条词缀的判定分成四种结果，其中**「存疑」是特意区分出来的**：

- **有效**：确定计入；
- **无效**：**确定**这条对当前角色没贡献（例如生命上限提升）；
- **存疑**：看起来像攻击词条，但条件认不出来（疑似 OCR 认错）——
  这种情况**绝不能当成 0**，否则该侧会被低估，进而误判"新的更好"去写入；
- **未识别**：OCR 文本根本不像一条词缀。

### 2. 界面流程

任务从**重构结果页**启动，这一页能同时看到「旧词缀技能 / 新词缀技能」两块面板
和「保留旧词缀 / 写入新词缀」两个按钮。

```
结果页：读「旧词缀技能」(= 我现在身上的) + 「新词缀技能」(= 本次候选)
  ├─ 旧词缀已达标 -> 点「保留旧词缀」收尾，任务完成
  ├─ 新的总攻击力更高 -> 点「写入新词缀」
  └─ 否则
       ├─ 普通模式：点「再次重构」原地换一批（留在结果页，不回主页）
       └─ 词缀锁模式：没有「再次重构」，点「保留旧词缀」
写入/保留之后游戏会强制回到主页 -> 点「词缀重构」回到结果页 -> 继续
```

为什么从结果页启动，而不是从主页（普通重构页 / 定向重构页）：

- 主页左下那块「词缀技能」面板 **显示不全** —— 词缀名一长就被面板自己截断，
  定向重构页上被锁定的那条还会被游戏自己的「已锁定」标记盖住；
- 结果页的两块面板都是干净完整的，旧词缀就是"我现在身上的"，判达标和择优最准；
- 能走到结果页本身就说明用户已经在重构页点过一次， **锁肯定设好了** 。

**锁定的那条怎么认**：锁定的词缀不会被重构，所以它在旧/新两批里文本完全一样。
逐行比对，只有一条相同就是锁定的那条；两批全变了则说明根本没锁，直接停下提示用户。

### 3. OCR 抗错

游戏内文字是带描边的小号字，OCR 认错一两个字很常见。除了把判定改成结构化匹配，
还做了几件事：

- **多武器互相验证**：一条武器词条通常列 2~3 把武器，OCR 认错其中一把时，
  靠另外一两把仍能确定所属武器组；跨组武器同时出现则判「存疑」；
- **易混字表**：属性名逐字比对 6 个候选（`尘↔辰`、`子↔孑`、`量↔重`、`数↔敉` 等），
  且必须**唯一胜出**才认，两个候选一样像时判「存疑」而不是瞎猜；
- **噪声判据**：一行必须有数字、且至少两个汉字才算读到（游戏里每条词缀都带数值）；
- **「攻击提升」被认错**：命中该四字里的两个字以上、又不是已知的非攻击词缀，判「存疑」
  （例如 `攻去提升22.7`）；
- **写后校验**：写入之后下一轮读到的旧词缀必须等于刚写进去的值，
  连续两次不符就停止（防止"点了写入但没生效"悄悄跑下去）。

判定层之外，所有按钮都靠 **OCR 认字 + 点文字框正中**，而不是写死坐标 ——
MaaFramework 对四元组形式的 `target` 会**在矩形内随机取点**，
矩形一大就会点到别的控件上。

## 四、用法

### 1. 软件内使用

先在游戏里**点一次「词缀重构」**，停在**重构结果页**再开始任务。

- **直接洗词缀**：在普通重构页点一次「词缀重构」进结果页即可；
- **词缀锁洗词缀**：先在**定向重构页锁好要保留的那条词缀**，再点「词缀重构」进结果页，
  并把「确认使用词缀锁」选成「是」。

如果启动时不在结果页，任务会直接停下并提示缺少哪个标记。

### 2. 怎么看日志

运行日志（`debug/agent.log`）会逐轮打印，例如：

```
已确认停在重构结果页，开始比较旧/新词缀
[第 1 轮] 旧 总=31.7 单条=22.7(可靠=True) | 新 总=34.0 单条=22.9(可靠=True)
⭐ 新词缀更优（有效总攻击力更高 34.0 > 31.7，还差 9.0 到目标），先写入新词缀保底
...
✅ 完成：有效总攻击力 43.0 ≥ 目标 42（...）
```

- `可靠=False` 说明这一侧有一行被判「存疑」，此时不会写入；
- `存疑`、`未识别` 的行会连同原文一起打出来，方便判断是不是 OCR 认错；
- 词缀锁模式会打印 `锁定的是第 2 条（旧/新两批里只有它没变）`。
