# 往世乐土合并说明

此开发分支在 `miaojiuqing/Maa_bbb` 的最新源码上，迁移现有 MuMu 全自动乐土实现。上游源码基线为提交 `7f181fb1529dd815d97ca115fe135bfd4cbbcf6f`，角色目前适配窈窕谍影·华裳。

## 合并范围

- 复用上游乐土任务的进入游戏、战前准备和周常领奖流程。
- 第一层刻印及关内流程交给 `ElysianStage`，负责对话、战斗、刻印、寻门、商店、逐层推进和结算。
- 第 17 层完成后进入任选英桀房间并退出，核对结算结果后接回周常领奖。
- 丽塔出招表放在 `characters/rita_elysian_huashang.json`，由角色执行器读取。
- 原界面的真我刻印输入、普通刻印优先级、门优先级和安卓商店策略传入关内执行器。
- 门识别模型沿用上游 `assets/resource/base/model/detect/best.onnx`。
- 新增 Python 依赖 `numpy` 和 `Pillow`，构建步骤复制角色配置并排除 Python 缓存。

战斗、刻印、寻门和商店算法沿用现有实现。本次先验证合并完整性，近期运行问题后续再实测排查。上游日常、深渊、智能洗词缀及原有桌面端流程继续保留。

## 开发与检查

源码目录使用 `assets/resource`、`assets/tasks` 和 `assets/interface.json`。打包后的程序使用根目录 `resource`、`tasks` 和 `interface.json`；迁移时不要将整个旧运行包覆盖到源码仓库。

准备开发环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
git submodule update --init --recursive
.\.venv\Scripts\python.exe tools/configure.py
```

接口与打包检查：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

资源检查：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/check_resource.py assets/interface.json
```

这些检查不连接模拟器，不代表新版已在游戏中完整通关。源码克隆不包含前端 exe，生成完整运行包仍需按上游构建流程准备前端、MaaFramework 和运行环境。

## 本地启动与同步

Windows x64 开发时，可借用官方 v1.13.6 的界面和运行库，在独立的 `install/` 目录运行当前源码。首次准备：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/prepare_local.py
```

脚本校验官方压缩包，准备随包 Python，安装与运行库匹配的 MaaFw 以及当前依赖，再同步任务、资源、角色出招表和 Python 代码。前端实际加载的 `maafw/` 库也会与 `runtimes/win-x64/` 对齐，避免前端和 agent 混用不同框架版本；更换前端库前会在本地 `deps/local-runtime/` 保留原库备份。完成后双击 `install/识宝小助手.exe`，标题显示“本地乐土测试版”。首次使用需在这个独立副本中选择模拟器及任务；不会从旧版复制本机配置。

后续修改代码、任务或角色出招表后，先停止任务并退出测试版，再执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/prepare_local.py --sync-only
```

重新打开测试版即可使用修改后的代码。若修改了 `requirements.txt`，执行不带 `--sync-only` 的完整准备命令更新依赖。同步保留测试版的配置与日志，关闭测试副本的自动更新，并刷新资源校验值；`install/`、依赖缓存和本机记录由 Git 忽略。测试版不要手动执行在线更新，以免本地修改被上游发布包覆盖。脚本检测到测试版仍在运行时会停止同步。

功能使用方式见 [往世乐土使用说明](往世乐土使用说明.md)。本机配置、虚拟环境、生成的 OCR 文件、日志、运行记录和打包目录由忽略规则排除。
